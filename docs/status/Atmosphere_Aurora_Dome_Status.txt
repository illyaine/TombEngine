Atmosphere Aurora / Dome status
================================

Branch: atmosphere_system
Progress: about 60 percent

Current branch state
--------------------
- The temporary Aurora shader prototype has been removed from the branch.
- `Sky.hlsl` is back to the normal TEN sky shader path and must not be used for Aurora routing.
- `RendererDraw.cpp` is back to the master draw path; the temporary extra sky-grid Aurora draw block has been removed.
- `Aurora.hlsli` is not part of the current branch anymore.
- Aurora profile data exists in the Flow/Atmosphere data model.
- A dedicated Aurora shader foundation now exists, but the renderer draw call is not mounted yet.
- The Aurora shader no longer depends on `FogColor.a` for visibility/fading.
- The Aurora shader no longer includes `CBCamera.hlsli`; it only depends on `CBAtmosphereAurora.hlsli`.
- Aurora intensity controls color brightness. Transparency controls alpha. Intensity only disables alpha when it is exactly zero.
- Aurora shader movement is slower than the removed prototype and the visible band is biased toward the upper sky.
- The shader uses a narrower effective width to avoid covering too much of the screen.
- `ConstantBufferRegister::AtmosphereAurora` is reserved as register 9 and matches `CBAtmosphereAurora.hlsli` register `b9`.

Added Aurora foundation files
-----------------------------
- `TombEngine/Shaders/CBAtmosphereAurora.hlsli`
  - HLSL constant buffer for Aurora colors, controls, wave parameters and time.
- `TombEngine/Shaders/AtmosphereAurora.hlsl`
  - Isolated fullscreen/sky-space Aurora shader.
  - Does not include or modify `Sky.hlsl`.
  - Uses three internal Aurora layers with different offsets and color contribution.
  - Uses intensity as brightness control, not as a hard visibility threshold.
  - Uses transparency as output alpha control.
  - Uses height, width, speed, waveScale and waveStrength as visible shape controls.
  - Does not use fog alpha or horizon marker values as routing/fade inputs.
  - Does not require the camera constant buffer.
  - Uses a reduced glow contribution and slower procedural drift.
- `TombEngine/Renderer/ConstantBuffers/AtmosphereAuroraBuffer.h`
  - Renderer-side 16-byte aligned constant buffer mirror.

Why the prototype was removed
-----------------------------
The previous test path tried to route Aurora through the normal sky shader and sky-grid/horizon drawing path. That caused fragile behavior: normal horizon layers could be affected by Aurora marker logic, and Aurora visibility depended too much on glow intensity and the legacy sky/horizon draw order.

That approach is not PR-quality and should not be kept.

Correct Aurora direction
------------------------
Aurora needs a dedicated atmosphere layer, not a `Sky.hlsl` marker hack.

The implementation direction is:

1. A separate Aurora shader.
2. Renderer-side constants populated from `Flow.Level.atmosphere.aurora`.
3. A clearly named and isolated draw path, e.g. `DrawAtmosphereAurora(...)`.
4. Explicit render order instead of `Color.w` sentinel values.
5. No changes to normal horizon layer rendering unless a legacy/atmosphere switch explicitly requires it.

Desired render order
--------------------
1. Atmosphere background / sky dome
2. Aurora layer
3. Celestial bodies: moon, planets, stars, Milky Way, comets
4. Optional legacy horizon for old levels
5. Weather
6. Rooms, objects, overlays

Open renderer work
------------------
- Add `CAtmosphereAuroraBuffer` to `Renderer` and bind it to `b9` for the Aurora pass.
- Populate the Aurora constant buffer from the Flow atmosphere Aurora profile.
- Add a clean renderer call, preferably `DrawAtmosphereAurora(...)`.
- Mount the pass only when:
  - at least one outside/sky room is visible,
  - `levelPtr->GetAtmosphereEnabled()` is true,
  - `levelPtr->GetAtmosphereAuroraEnabled()` is true,
  - intensity and transparency are greater than zero.
- Keep the pass isolated from legacy sky, horizon, starfield and lens flare draw code.
- Keep `RendererDraw.cpp` unchanged until the existing sky/horizon render order is fully mapped.

Completed renderer foundation work
----------------------------------
- Added `Shader::AtmosphereAurora` and loaded `AtmosphereAurora.hlsl` in `ShaderManager`.
- Reserved `ConstantBufferRegister::AtmosphereAurora = 9` for the Aurora pass.
- Removed the unused camera constant-buffer dependency from `AtmosphereAurora.hlsl`.
- Decoupled Aurora output alpha from intensity, so low intensity still remains renderable when transparency is set.
- Tuned the Aurora shader to be slower, narrower and biased toward the upper sky.
- Kept the `TombEngine.vcxproj` diff limited to necessary file additions.
