# Atmosphere Runtime Read Path Concept

## Purpose

This document describes how TombEngine should later read atmosphere data at runtime without creating a direct dependency on Tomb Editor and without activating renderer behavior before the data model is stable.

## Current State

The current branch adds a `Flow.Atmosphere` data shape and stores it on `Flow.Level`.

Current data owner:

```text
Level::Atmosphere
```

Current compatibility path:

```text
Level::GetWeatherType()
Level::GetWeatherStrength()
Level::GetWeatherClustering()
```

These getters continue to return legacy weather fields unless `level.atmosphere.enabled` is true.

## Runtime Boundary

Runtime code should not depend on Tomb Editor object parameter internals.

The runtime should see only exported data:

```text
Flow.Atmosphere
Flow.WeatherProfile
Flow.WindProfile
Flow.AuroraProfile
Flow.AtmosphereEffectProfile
```

Later, if Tomb Editor exports runtime metadata instead of Flow/Lua, that metadata should be converted into the same internal atmosphere runtime state before rendering.

## Suggested Non-Activating Runtime Path

Before adding renderer behavior, add a small read path:

```text
Level Flow data
        ↓
Atmosphere runtime snapshot
        ↓
AtmosphereController update
        ↓
Renderer-specific consumers later
```

The first runtime snapshot should not render anything. It should only collect resolved values.

Recommended first snapshot fields:

```text
bool Enabled
WeatherType WeatherType
float WeatherStrength
bool WeatherClustering
WeatherQuality WeatherQuality
float WindDirection
float WindStrength
float WindGustStrength
float WindTurbulence
bool AuroraEnabled
float AuroraIntensity
float AuroraSpeed
```

Local/nullmesh effect data should stay read-only and inactive until Tomb Editor Object Parameters can author it cleanly.

## Why a Snapshot

A snapshot prevents renderer code from directly depending on Flow structures. This is important because the same runtime data may later come from:

```text
- Hand-written Flow/Lua for global settings.
- Tomb Editor generated Flow/Lua.
- Tomb Editor generated runtime metadata.
```

Renderer code should receive one stable resolved shape.

## Suggested Controller Phases

Recommended safe sequence:

```text
1. Add AtmosphereRuntimeSnapshot with resolved global values only.
2. Add an AtmosphereController shell that can update the snapshot.
3. Keep renderer calls disabled.
4. Add Aurora runtime data consumption.
5. Add Aurora renderer layer.
6. Add global generated atmosphere layer.
7. Add local/nullmesh/room/volume effects after Tomb Editor Object Parameters exist.
```

## Compatibility Rule

The snapshot must preserve the existing weather fallback:

```text
if level.atmosphere.enabled == false:
    use legacy level.weather, level.weatherStrength, level.weatherClustering
else:
    use level.atmosphere.weather.*
```

This avoids breaking existing levels.

## Local Effects Rule

Local atmosphere effects should not become the normal hand-written scripting workflow.

The runtime may later consume them from `Flow.Atmosphere.effects`, but those entries should normally be generated by Tomb Editor's Object Parameter System.

The first runtime implementation should therefore ignore local effects or keep them inert until the editor authoring path exists.
