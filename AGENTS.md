# Repository Development Rules

## Binding Quality Principle (2026-10-23)

> Sorgfalt vor Geschwindigkeit. Qualität vor Quantität. Jede Funktion sauber entwickeln, gründlich prüfen und zuverlässig umsetzen. Keine halben Lösungen, keine unnötige Komplexität und keine Kompromisse bei der Stabilität.

In English: Care before speed. Quality before quantity. Develop each feature carefully, verify it thoroughly, and deliver reliable results. No half-finished solutions, unnecessary complexity, or compromises on stability.

### Mandatory working rules

- Read current project documentation, source, and relevant interfaces before editing. Never rely on unverified assumptions.
- Make focused, comprehensible changes. Prefer existing architecture and simple solutions over unnecessary abstractions.
- Check error paths, data integrity, security, compatibility, and regressions whenever relevant to the task.
- Run appropriate builds and tests when possible. Do not claim tests passed or work is complete without actual verification.
- Fix root causes instead of concealing symptoms. Clearly identify incomplete work, risks, and checks that could not be performed.
- Preserve project-specific instructions and avoid unrelated changes. Apply stricter compatible existing project rules.
